Issues in.
Reviewed, tested changes out.

A software factory built on Claude Code, shown on a small demo app.

You describe what you want in an issue. A line of AI agents and plain scripts turns it into a tested, reviewed change, and leaves a written record of every step.

issuespecbuildchecksreviewmerged change

One agent in one long chat does every job at once

It writes the code, runs the tests, reviews the result and decides it is done. Three things go wrong.

  • It grades its own work.The same context that wrote the bug reads the code again and finds it reasonable.
  • It can move its own goalposts.A failing test is a problem to solve, and deleting the test solves it.
  • Nothing is written down.When the chat ends, why a change was accepted is gone with it.

The factory's answer is the one a real factory gives: separate stations, a fixed route between them, and paperwork that travels with the job.

The branch cannot change the checks it is judged by

    

      

        
The gate is a script, not an agent. It runs the checks from the main branch inside the job's working copy, and fails any branch that edits a protected file.

        

          
          
          
        

        

      

      


# factory/checks.sh, read from main
ruff check .
python3 -m pytest -q

# factory/config.json
"protected_paths": [
  "factory/checks.sh",
  "factory/config.json"
]

        
A failed gate sends the log back to the builder. No reviewer is started, so no review is spent on code that does not pass its own tests.

It stops and asks when a person should decide

    

      
    
        
  • The issue is unclear.Intake posts its question on the issue and waits. Answer it and the job resumes.
    • 
        
  • The request does not belong.Intake rejects it and says why. Nothing is built.
    • 
        
  • Three rounds were not enough.Build, gate and review may repeat three times. After that the job goes to a person, not round four.
    • 
      

      
    
        
  • The approver escalates.Each project lists what a person must always see. In this demo: anything that exposes or exports attendee emails.
    • 
        
  • The merge is not clean.A conflict, or checks that fail after syncing with main, goes to a person.
    • 
        
  • You stay in charge.Merge it yourself, send it back with feedback, or reject it. The factory never deploys.
    •

Intake noticed the issue left two cases open and settled them the way the existing code already behaved. It wrote down that it had done so and how to overrule it. The approver ran the tests again before merging.

      
The run also stalled once. The routing script had no price for a new model and refused to continue until one was added. A factory that stops when it cannot account for something is doing its job.

In local mode an issue is a text file, and the label factory on it is the trigger. With no pull request, the factory merges the branch itself once the gate has passed again, and git refuses the push if main moved in the meantime.

    

  






  

    
Run it on your own machine

    

      


git clone https://github.com/fayssal-elmofatiche/factory-sandbox.git
cd factory-sandbox
factory/local-setup.sh ~/factory-demo
cd ~/factory-demo
claude          # then type: /factory run

        
macOS, Linux, or Windows with WSL. You need git, Python 3.10+ with pytest and ruff, and Claude Code. Details are in docs/local-mode.md.
